# Начало работы

Курс литературного мастерства, ядро — 396 часов работы. Сроки считаются по вашему реальному расписанию: при 9 ч/нед это около 46 недель, при часе в день — чуть больше года, при 5 ч/нед — около полутора лет.
Вы учитесь вместе с агентом (Claude Code или Codex): он объясняет, выдаёт пакеты заданий, разбирает ваши этюды, проверяет и ведёт ваше личное состояние. Материал курса общий, состояние — только ваше.

## Что нужно

- macOS, Linux или Windows (WSL или Git Bash), `git`
- Python 3.11 или новее; скрипты курса без внешних зависимостей. Системный `python3` на старых macOS — 3.9, его не хватит: `brew install python@3.13` и проверьте `python3 --version`
- Claude Code или Codex CLI (или расширения для VS Code)
- Свои книги или доступ к библиотеке: курс текстов не распространяет ([resources.md](resources.md))
- Отдельная папка (лучше — приватный git-репозиторий) для своих рассказов — Project A «Сборник» ([07-project-a.md](07-project-a.md))

## Установка

```bash
git clone https://github.com/efremovaanzhelika29-star/student-literate-course.git literary-course
cd literary-course
python3 bin/init_learner.py --hours 9 --git
```

`--hours` — примерная оценка бюджета для профиля. Точное расписание (минуты по дням, перерывы) агент спросит первым вопросом онбординга и посчитает сроки командой `bin/plan.py`. Даты в трекере появятся только после того, как вы их согласуете; пропущенное занятие не создаёт долг.

Скрипт создаёт `state/` — ваш прогресс, проверки, журнал уроков, профиль, портфолио приёмов. Существующее состояние он не перезаписывает никогда. `--git` делает `state/` отдельным git-репозиторием, чтобы история прогресса не терялась; курс сам `state/` не отслеживает.

## Первая сессия

Откройте агента **в корне курса** (не в `state/`) и напишите «начнём». Агент прочитает `CLAUDE.md`/`AGENTS.md` и проведёт онбординг:

1. Спросит расписание и посчитает сроки.
2. Заполнит с вами `state/profile.md`: опыт письма и чтения, цели писательские и актёрские, ограничения, путь к папке Сборника.
3. Проведёт аудит базы из `00-rules.md` — без подсказок, честно. Опыт не засчитывает темы автоматически.
4. По итогам выберет старт — обычно T01, иногда с сокращением отдельных недель.

Дальше работают команды `/status`, `/learn`, `/check`, `/review`, `/mock` (в Codex — те же просьбы обычными словами). Как устроен цикл — [10-learning-loop.md](10-learning-loop.md), правила ментора — [mentoring/harness.md](mentoring/harness.md).

## Права агента

Скрипты курса пишут ваш прогресс в `state/`, поэтому агенту нужно право записи в каталог курса; сеть для учёбы не нужна.

- Claude Code: `bin/track.py` и `bin/practice.py` разрешены в `.claude/settings.json`; на остальные команды (`bin/lesson.py`, `bin/plan.py`) агент спросит разрешение. Править файлы в `practice/` ему запрещено: ваши тексты меняете только вы.
- Claude Code: при первом запуске подтвердите доверие к каталогу курса — иначе не сработает хук из `.claude/settings.json`, который при старте показывает, где вы остановились. Свои постоянные разрешения кладите в `.claude/settings.local.json` (курс его игнорирует).
- Codex: режим `workspace-write`. В `read-only` агент не сможет сохранить прогресс.

Оценки и статусы меняются только командами `bin/track.py`, не ручной правкой `state/topics.json`.

## Работа в IDE

Удобнее всего учиться в VS Code: слева ваш текст, справа панель агента, снизу терминал.

1. Extensions (`Cmd+Shift+X` / `Ctrl+Shift+X`): **Claude Code** (Anthropic) и/или **Codex** (OpenAI).
2. Вход в панели расширения — по подписке, без ключей API: Claude Code — через аккаунт Claude (Pro, Max, Team или Enterprise); Codex — Sign in with ChatGPT, режим с правом записи.
3. File → Open Folder → корень курса. Тогда агент прочитает правила из `CLAUDE.md` или `AGENTS.md`.
4. Для удобного письма: включите перенос строк (`View → Word Wrap`) и, по желанию, расширение для подсчёта слов/знаков в Markdown.
5. Нужен прокси — у редактора и агентов он настраивается раздельно: агенты берут его из переменных окружения; запускайте VS Code из терминала, где выставлены `HTTPS_PROXY`/`HTTP_PROXY` (`code .` в корне курса).

Как идёт пакет в IDE:

- Выдавая пакет, ментор создаёт папку `practice/<пакет>/`: `answer.md` — ответы на вопросы, `map.md` — карта разбора, `t1_stage1.md`, `t1_stage2.md` — этапы этюда.
- Прогнозы пишете в `answer.md` до чтения продолжения, тексты — в файлах. Готово — пишете агенту «проверь T04-P3». Вставлять текст в чат не нужно: агент сам читает файлы и запускает формальную проверку `bin/practice.py run`.
- Ошибки разбираются по одной. Исправили файл — пишете «исправила». Агент ваши файлы не правит; пример правки, если попросите, покажет в чате.
- Быстрый вопрос: выделите фразу в редакторе и спросите — расширение передаёт агенту открытый файл и выделение.

`practice/` исключена из git курса (`.gitignore` и `.git/info/exclude`): обновление курса её не трогает.

## Учёба на нескольких устройствах

Курс, ваш прогресс и ваши рассказы — это **три разных репозитория**, и каждый синхронизируется отдельно:

| Что | Где | Как синхронизировать |
|---|---|---|
| Курс | этот репозиторий | `git pull --ff-only` (или «обнови курс») |
| Ваше состояние | `state/` внутри клона курса, свой git (`--git`) | приватный репозиторий на GitHub, `git push` / `git pull` |
| Сборник | папка рядом с курсом, свой git | приватный репозиторий на GitHub |
| Практика | `practice/` | не синхронизируется по умолчанию; лучшие этюды переносите в Сборник |

**Первое устройство — один раз:**

```bash
# создайте на GitHub ПРИВАТНЫЙ пустой репозиторий, например literary-state
cd literary-course/state
git remote add origin https://github.com/<ваш-логин>/literary-state.git
git push -u origin HEAD
```

**Каждое новое устройство:**

```bash
git clone https://github.com/efremovaanzhelika29-star/student-literate-course.git literary-course
cd literary-course
git clone https://github.com/<ваш-логин>/literary-state.git state   # НЕ запускать init_learner
./bin/track.py validate && python3 bin/lesson.py validate
```

**Привычка, без которой синхронизация не работает:** перед учёбой — `git -C state pull`, после — `git -C state add -A && git -C state commit -m "урок" && git -C state push`. Можно попросить агента: «синхронизируй прогресс» (pull перед уроком, commit и push после). Не работайте одновременно на двух устройствах — иначе будут конфликты в `state/`.

**Облачная сессия Claude Code (claude.ai/code):** подключите к сессии репозиторий курса; `state/` в облаке не сохраняется между сессиями, поэтому в начале попросите агента склонировать ваш приватный `literary-state` в `state/`, а в конце — сделать push.

**Только телефон / обычный чат:** используйте проект на claude.ai с единым файлом курса (`tools/build_bundle.py`, раздел в README). Трекер там недоступен; прогресс переносится блоком «ВЕДОМОСТЬ».

## Обновление курса

Ветка `main` — последняя версия. Обновление не трогает ваш `state/`:

```bash
git pull --ff-only
./bin/track.py validate
python3 bin/lesson.py validate
```

Проще — попросить агента: «обнови курс». Он выполнит эти команды, перескажет изменения и ничего не сольёт поверх ваших правок без вопроса. Если `validate` после обновления ругается — не правьте `state/topics.json` руками, попросите агента разобраться.

## Приватность: куда уходят ваши данные

| Где | Что там | Кто видит | Срок и удаление |
|---|---|---|---|
| `state/` на вашем компьютере | Ответы, протоколы проверок, слабые места, журнал занятий, профиль | Только вы и ваш агент | Пока сами не удалите. В git курса — в `.gitignore` |
| Ваш приватный репозиторий `literary-state` | То же, если включили синхронизацию | Вы (и те, кому дадите доступ) | По правилам GitHub; удаляется вместе с репозиторием |
| `practice/` и Сборник | Ваши этюды и рассказы | Только вы и ваш агент | Пока сами не удалите |
| Чат с ИИ-агентом (Claude Code, Codex) | Всё, что вы пишете, и файлы, которые агент читает, включая `state/` и рассказы | Провайдер модели (Anthropic, OpenAI) по правилам вашего аккаунта | По правилам провайдера; проверьте в настройках аккаунта, используются ли чаты для обучения моделей |

Не публикуйте `state/` и неопубликованные рассказы: многие журналы и конкурсы принимают только неопубликованное. Не вставляйте в чат пароли и чужие персональные данные.
